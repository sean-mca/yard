**Part 1: Rust SDK Tutorial (primary audience per D-13, D-14)**

Walk through building a minimal provider plugin from scratch. Steps:

1. Create a new Rust project: cargo init --name yard-plugin-example
2. Add yard-plugin-sdk dependency: yard-plugin-sdk = { version = "0.1" } (or path dep for local dev). Note that yard-plugin-sdk re-exports everything needed -- no direct yard-structs dependency required.
3. Implement PluginHandler trait (8 methods): name(), version(), validate(), codegen(), deploy(), destroy(), verify(), schema(). Show the minimal implementation from RESEARCH.md Code Examples section. Explain what each method does and what it receives/returns.
4. Create main.rs entry point: call PluginServer::run(MyProvider). Explain that this is a diverging function that handles the stdio protocol.
5. Build for your platform: cargo build --release. The binary goes to target/release/yard-plugin-example.
6. Test locally: copy the binary to .yard/plugins/yard-plugin-example-0.1.0-{os}-{arch} in a yard project directory. Add plugin_version: "0.1.0" and plugin_source: "file:///..." to a job.yaml. Run yard plan to verify.
7. Release to GitHub (D-16): create a GitHub release with tag v0.1.0. Upload platform-specific binaries following the naming convention: yard-plugin-example-0.1.0-{os}-{arch}. Supported platforms: aarch64-apple-darwin, x86_64-apple-darwin, x86_64-unknown-linux-gnu, aarch64-unknown-linux-gnu. Show the plugin_source URL template that users put in their job.yaml.

Cover the TOFU checksum model (D-16): explain that yard.lock records SHA-256 checksums per-plugin per-platform on first download. The lock file should be committed to version control. Team members on different platforms accumulate checksums automatically.

**Part 2: JSON Protocol Spec (for non-Rust developers per D-13)**

Document the raw protocol for developers who want to build a plugin in another language (Go, Python, etc.).

Protocol flow:
1. yard spawns the plugin binary as a child process
2. Plugin writes a handshake line to stdout (JSON: protocol_version, name, version, capabilities)
3. yard writes a request line to stdin and closes stdin
4. Plugin reads the request, may emit progress lines to stdout (JSON: type "progress", message, percent)
5. Plugin writes a response line to stdout
6. Plugin exits

Message formats: reference the types in yard-structs/src/plugin.rs. Document the 6 operations (validate, codegen, deploy, destroy, verify, schema) with their request fields and response shapes.

Key constraints:
- stdout is the protocol channel. All logging goes to stderr.
- Protocol is line-delimited JSON (one JSON object per newline)
- Plugin must exit after handling one request (one process per operation)
- Protocol version must match (currently version 1)
