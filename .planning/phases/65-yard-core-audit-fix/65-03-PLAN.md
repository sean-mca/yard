| YAML config -> resolve.rs -> parsing.rs | Untrusted YAML deserialized and resolved through config cascade |

| Filesystem state files -> storage.rs | State files read from local FS or S3, could be tampered |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-65-05 | Tampering | storage.rs state deserialization | medium | accept | State files deserialized via serde with typed structs. Tampered state causes incorrect diff (stale deploy), not code execution. Accept because yard is a CLI tool run by the operator who owns the state files. |
| T-65-06 | Tampering | providers/ AWS SDK calls | low | accept | AWS SDK handles request signing and TLS. Provider code constructs API calls from validated config. No raw HTTP. |
| T-65-07 | Denial of Service | orchestrate.rs locking | low | mitigate | Per-job locking with TTL backstop for crash recovery prevents permanent lock starvation. Already implemented in storage.rs. |
